# 两条并行实现的差异与合并建议

写于 2026-11-01，由 lovezexiaoze 提出，供维护者决策。

## 背景

`main` 分支和 `integrate` 分支各自独立演进出**同一套系统的两个完整实现**，
两条历史没有共同祖先（`integrate` 是从本地仓库推送上去的独立历史）。

直接 `git merge` 会产生 **23 处冲突**，而且冲突的是同一批核心文件
（`main.py`、`config.py`、`providers/*`、`frontend/styles.css` 等），
逐行合并风险很高。

## 两边各有什么

### main（joystudying / Joy 的成果）

| 能力 | 文件 |
|---|---|
| 复盘评价 | `backend/app/core/evaluator.py`、`providers/evaluator_deepseek.py` |
| PDF / Word 导出 | `backend/app/export.py` |
| 数据模型与仓储 | `backend/app/models.py`、`db.py`、`repo.py` |
| 实时语音 WS | `backend/app/ws/voice.py`、`providers/realtime_volc.py` |
| 会话接口 | `backend/app/routers/sessions.py` |
| 前端复盘/记录/语音 | `frontend/review.js`、`records.js`、`voice.js` |

**核心价值：评价链路和报告导出**——这是产品的立身之本，`integrate` 完全没有。

### integrate（本分支的成果）

| 能力 | 文件 |
|---|---|
| 真双工实时语音（已实测跑通） | `providers/realtime_volc.py`、`api/ws_voice.py`、`frontend/js/realtime.js` |
| 可插拔 Provider 抽象 | `providers/base.py`、`__init__.py`、`llm_deepseek.py`、`tts_edge.py` |
| 数据完整性 | `db/schema.sql`、`db/repo.py`（幂等、事务、失败回滚） |
| 私有设定防护 | `services/persona.py`、`guard.py`（注入检测 + 输出黑名单） |
| 自动化测试 | `backend/tests/`（**48 条**，含 WebSocket、幂等、守卫） |
| 架构守卫 | `scripts/check_boundaries.py`（分层越界自动拦） |
| 文档体系 | `docs/声明.md`、`架构说明.md`、`参与指南`、`CHANGELOG` |
| 接入配置页 | `frontend/setup.html`（在线填密钥，只允许本机） |

**核心价值：可维护性证据**——测试、边界检查、文档、实测记录。

## 实测结论（integrate 侧，可直接复用）

1. **火山端到端实时语音可跑通**：握手 101 → event 50 → event 150，
   实测老师 8.9 秒语音 → 学生 8.4 秒语音，识别文本与回复都正常。
2. **下行音频是 float32 / 24k**，按 int16 读会变成噪音（踩过）。
3. **协议是二进制帧**，JSON 文本会被拒（`unsupported protocol version`）。
4. **500 ChatTTSText 在该会话里不产生音频**，`output_mod` 三种取值均被忽略——
   端到端模型不接受"指定台词"，情绪只能通过人设/音色/语速在会话级控制。
5. 详细帧格式、事件号、排错对照见 `docs/实时语音验证记录.md`。

## 建议的合并方式（不是 git merge）

按模块挑选，而不是按文件硬合：

1. **以 main 为基线**，保留其评价、导出、数据模型
2. **从 integrate 移入**：
   - `backend/tests/`（48 条测试，直接能跑，是最大的增量价值）
   - `scripts/check_boundaries.py`
   - `services/persona.py` + `guard.py`（私有设定与输出防护）
   - `docs/`（声明、架构说明、接入指南、验证记录）
   - `api/settings.py` + `frontend/setup.html`（在线配置）
   - 真双工前端 `frontend/js/realtime.js` 与 `api/ws_voice.py`（若 main 的 `ws/voice.py` 尚未跑通真双工）
3. **数据库层二选一**：main 用 SQLAlchemy（`models.py`），integrate 用裸 `sqlite3` + 手写 schema。
   建议保留 main 的 ORM 方向，把 integrate 的幂等/事务逻辑移植进去。

## 需要维护者确认

- [ ] 以哪条分支为基线
- [ ] 数据库层保留 ORM 还是裸 SQL
- [ ] 真双工用哪一版实现（两边都有 `realtime_volc.py`，协议细节可能不同）

在确认之前，两边的 `integrate` 与 `main` 不建议强行合并。
