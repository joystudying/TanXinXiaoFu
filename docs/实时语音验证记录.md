## 三、帧格式（这是最容易踩坑的地方）

服务端**只认二进制帧**。直接发 JSON 文本会被回：

```
decode ws request failed: unsupported protocol version 7
```

（因为 `{` 的 ASCII 是 0x7B，被当成版本号 7）

正确帧结构：

```
┌ 4 字节头 ────────────────────────────────┐
│ byte0: version(4位) | header_size(4位)   │  版本 0001，头长 0001（=4字节）
│ byte1: message_type(4位) | flags(4位)    │  客户端全量请求 0001；flags 0100=带 event
│ byte2: serialization(4位) | 压缩(4位)    │  JSON 0001；gzip 0001
│ byte3: 保留                              │
└──────────────────────────────────────────┘
   event(4字节, 大端)
   [可选] session_id 长度(4字节) + session_id
   payload 长度(4字节, 大端)
   payload（**gzip 压缩后的 JSON**）
```

三个关键点，缺一个服务端就不回包：
1. `flags` 必须是 `0b0100`（带事件位），不是 0；
2. payload **必须 gzip**；
3. `X-Api-App-Key` 是 `PlgvMymc7f3tQnJ6`，不是别处流传的 `aGjiRDfUWi`。

## 四、事件号

| 方向 | event | 含义 |
|---|---|---|
| 上行 | 1 | StartConnection |
| 上行 | 100 | StartSession（带 session_id） |
| 上行 | 200 | TaskRequest（音频帧，message_type=0010 二进制） |
| 上行 | 102 | FinishSession |
| 上行 | 2 | FinishConnection |
| 下行 | 50 | ConnectionStarted（回 session_id） |
| 下行 | 150 | SessionStarted（回 dialog_id） |

```

StartSession     → event=150 session_id=37297fde-…  payload={"dialog_id":"e3b21f1d-f892-49e1-bf7a-55bb507d1f83"}
```

## 五、音频规格

| 项 | 上行（老师） | 下行（学生） |
|---|---|---|
| 格式 | **PCM16**、单声道、16000 Hz、小端 | **float32**、单声道、24000 Hz |
| 分片 | 建议 20ms 一包（640 字节） | — |
| 传输 | gzip 后放进 TaskRequest（event 200，message_type=0010） | 放在响应 payload 里 |
| 电平 | 人声 RMS 建议 −31.7 ~ −23.9 dBFS | — |

**注意一**：上下行位深不一样——上行 int16，下行 float32。按 int16 读下行会得到噪音。
（这个坑踩过：第一版录音全是杂音，存成 WAV 后像白噪音；ZCR 0.49，改成 float32 后 ZCR 0.065，正常。）

**注意二**：关麦后必须发静音保活，否则服务端超时、模型不响应。
