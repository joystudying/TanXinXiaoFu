## 一、会导致实现卡死的矛盾

### Q1 失败后同 key 重试走不通

- 文档 11.2 说：`failed` → 同 key 重试 → 重新置 `pending`。
- 文档 9.4 的 `begin_turn` 代码只有两个分支：`status == 'done'` 返回缓存，否则一律返回 `in_flight`
  → `failed` 会被判成"处理中"，永远 409，重试永远不会成功。
- 需要拍板：按 11.2 实现（补 `failed` 分支，重新置 pending）？还是失败后换新 key？

### Q2 超时/失败时 teacher 那一句留不留

- 文档 6.4 表格：模型超时 → "不写 turns"。
- 文档 9.4：`begin_turn` 在事务里已经 `INSERT INTO turns(role='teacher')` 了。
- 两者冲突。需要拍板：失败时删掉这条 teacher 记录，还是保留（对话记录里能看见"老师说了但学生没回"）？

### Q3 同一会话并发会撞主键

- 模型调用在事务外（7.3 要求），所以两个**不同 key** 的并发请求会分别拿到 turn_no=3、4；
  第一个调完写 student=4 时，与第二个已占用的 teacher=4 主键冲突。
- 文档 11.3 只列了"同 key 重试"，没覆盖"不同 key 并发"。
- 需要拍板：加会话级串行（`sessions` 上 pending 标记 / 乐观锁），还是只靠前端按钮 disabled？

### Q4 提示词以哪份为准

- 10.1 是完整的可直接用版本；9.3 是模板版本。两者不一致（口头禅、反问句、few-shot 10.2 没进模板）。
- 需要拍板：以 10.1 为唯一真源、9.3 的 `persona.py` 只做字段填充？

### Q5 `/api/metrics` 没有接口定义

- 13.2 前端要 `POST /api/metrics` 上报 asr/model/tts 三段耗时。
- 第 6 节接口清单里没有这个接口。
- 需要拍板：补一个接口规格，还是改成只写服务端日志（前端不上报）？

## 二、验收条款目前无法执行（建议改文档）

## 三、代码级隐患（不阻塞，但实现时别照抄）

### Q9 模板格式化会炸

9.3 用 `SYSTEM_TEMPLATE.format(...)`。案例文本里只要出现 `{` 或 `}`（LaTeX、JSON、代码片段都可能有），
`str.format` 直接抛 `ValueError`。
建议改用 f-string 分段拼接，或 `string.Template` + `safe_substitute`。

### Q10 私设黑名单只是弱保险

9.5 的 `private_keywords` 按「≥3 字、按标点切分」取词，模型把"父亲生病住院"说成"我爸住院了"就不命中。
建议：文档里明确它只防"原文照抄"，真正的防线是提示词规则 + 15.4 的 20 条人工测试。

### Q11 配置路径依赖当前目录

`config.py` 的 `env_file=".env"` 和 `db_path="data/tanxin.db"` 都相对 cwd。
换个目录启动就会读不到 .env、把库写到别处。
建议：基于 `Path(__file__).resolve().parents[2]` 计算项目根。

### Q12 文件清单与测试清单不一致

4.4 目录里没有 `test_timeout.py`、`test_closed.py`，16.1 里却列了。补进目录树。

### Q13 owner_id 只说了没做

15.1 T3 说「预留 owner_id 字段」，但 7.1 的 `sessions` 表没有这个字段。补字段或删这条。
