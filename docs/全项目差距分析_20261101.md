**语音对练这条链路已经超额完成（做到了 PRD 不要求的真双工），但产品的核心价值——复盘评价与引用校验——一行代码都没有。**

## 三、三条链路现状

### 语音对话链路 — 完成度约 95%

已具备：ASR、学生角色模型、TTS、按轮落库、幂等、失败回滚、真双工实时语音。
未具备：PRD 7.2 要求的「学生转写 = 实际用于合成的文本」在真双工模式下无法保证。

### 证据评价链路 — 完成度 0%

PRD 11.4 要求的五步，一步都没有：
```
读取已结束对话 → 按轮切分补上下文 → RAG 检索并重排 → 独立评价模型 → 校验引用与输出
```
缺的东西按依赖顺序：
1. 评价量规（五维的分档、扣分条件）——**PRD 16.1 自己列为待确认**
2. 评价模型调用（且必须与学生角色模型分开）
3. 引用校验（PRD 8.4 反复强调：引用不存在、说话人错误 → 不能作为有效证据）
4. 报告数据模型与状态机（13.3：未请求/待生成/生成中/完成/失败）
5. PDF / Word 导出（9.4）

### 知识建设与运行约束 — 完成度 5%

已有：版本化字段（`cases.version`、`case_version`）、幂等与重试、密钥只在服务端。
缺：知识条目表、来源与审核状态、RAG 检索与重排、运行日志脱敏。

### 危机专项 — 完成度 0%

只有界面占位。PRD 10.1 明确要求校内协作流程由专业人员审核后才能成为正式内容。

## 四、三个必须拍板的冲突

### 冲突一：技术栈对不上

| | PRD 第 11.1 节 | 实际代码 | 合作仓库 |
|---|---|---|---|
| 前端 | Vue 3 | 原生 HTML + ES Module | 原生 HTML |
| 数据库 | PostgreSQL + Alembic | SQLite + 手写 schema.sql | SQLite |
| 用户体系 | 有账号与权限校验 | 无，单机演示 | 无 |

这是**评审材料与代码不一致**，不是能力问题。二选一：
- 改 PRD 措辞（改成"原生前端 + SQLite，可按需迁移"）——成本半小时
- 真迁移（Vue3 重做前端约 5–8 天；PG + Alembic 约 1–2 天）

### 冲突二：真双工 vs 按轮

PRD 7.5 写得很明确：**「首版采用按轮次对话，不要求连续语音打断。」**

我们做了真双工，反而带来三个新问题：
1. **轮次没有边界**——评价链路的第一步就是"按轮切分"，真双工没有清晰的轮
2. **转写不一致**——PRD 7.2 要求学生转写等于实际朗读文本；端到端模型自己组织语言，我们拿到的是它输出音频的识别结果，会有偏差
3. **成本**——真双工按音频时长计费，比按轮调用贵

建议：**按轮模式作为默认**（PRD 合规路径），真双工作为"进阶演示"开关保留。

### 冲突三：评价模型必须独立

PRD 3.4 把「学生角色模型」和「评价模型」列为两个角色，11.4 要求"角色对话和谈后评价分开处理"。

现在只有一个 DeepSeek。如果既让它演学生又让它当评委，会出现**角色冲突**：它知道自己刚才说了什么，评分会偏向自己的表演。这条必须分开（换模型或至少换 system prompt + 独立会话）。

## 五、建议的优先级（按"不做就白做"排序）

### P0 · 不做后面全废（约 1 天）

1. **补齐 18 个案例**，加 `source_type`、`review_status` 字段
   没有案例，选择页、谈前准备、复盘的案例版本对齐都演示不了
2. **轮次归一**：真双工的对话输出也落成 turn 记录，保证复盘有地基

### P1 · 产品核心（约 2–3 天）

3. **复盘评价链路**（先不做 RAG）
   - 五维打分（量规先用简化版，等负责人确认）
   - **引用校验必须有**：每条评价绑定 teacher 原话 + turn_no，校验通过才算有效
   - 依据不足的维度标"依据不足"，不记零分（PRD 8.4 / 验收 6）
4. 报告数据模型 + 生成状态机

### P2 · 补全闭环（约 1–2 天）

5. 训练记录列表、继续、删除
6. 重练关联
7. PDF / Word 导出（同一份快照）

### P3 · 加分项（各 3–5 天）

8. 知识库 RAG + 重排
9. 危机专项（等专业审核）
