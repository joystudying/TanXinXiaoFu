## 1. 一页看懂：分层与依赖方向

```
                    ┌─────────────────────────────┐
  浏览器 ──HTTP──►  │ api/      薄接口层           │  校验入参 → 调下一层 → 拼响应
                    └─────────────┬───────────────┘
                                  │ 只能往下调
                    ┌─────────────▼───────────────┐
                    │ services/ 业务层             │  编排、模型、人设、幂等、守卫
                    └─────────────┬───────────────┘
                                  │ 只能往下调
                    ┌─────────────▼───────────────┐
                    │ db/       数据层             │  唯一 SQL 出口
                    └─────────────┬───────────────┘
                                  ▼
                            SQLite (WAL)

  横切：config.py（配置）  errors.py（错误形状）  deps.py（注入）
```

**依赖只能单向往下**。反向依赖（db 调 services、services 写 SQL、api 直接调模型）一律禁止。

### 每个层能改什么、不能改什么

| 层 | 可以做 | 禁止 |
|---|---|---|
| `api/` | 参数校验、调 repo/services、拼响应、抛 `ApiError` | 写 SQL、`import httpx`、拼 prompt |
| `services/` | 编排、调模型、拼 prompt、做守卫 | 写 SQL、直接读 `sqlite3` |
| `db/` | 所有 SQL、建表、迁移 | `import` services、发 HTTP |
| `frontend/` | DOM、状态机、调接口 | 存私有设定、直连模型 |

### 边界的机器检查

```powershell
python scripts\check_boundaries.py
```

四项检查，任一项失败即退出码非 0，可以直接挂进提交前钩子：

1. `services/` 里不出现 `SELECT|INSERT|UPDATE|DELETE`
2. `api/` 里不出现 `import httpx`
3. `db/` 里不出现 `from ..services`
4. 全仓库不出现硬编码的 `sk-` 密钥

## 3. 六项决策的落地约定

前面六条待确认问题已经拍板，这里写成"代码里具体长什么样"，实现时照做。

### D-1 / D-2 失败即回滚，允许同 key 重试

- `begin_turn` 遇到 `status='failed'` 时：把该行重置为 `pending`、重新分配 `turn_no`、重写 teacher 行；
- `mark_failed` 除了把 `request_log` 置 `failed`，**还要删掉本次已经写入的 teacher 行**（保证 `turns` 不留半轮）；
- 结果：失败后对话记录与失败前完全一致，重试等价于重来一次。

> 为什么这样选：`turns` 里出现"老师说了、学生没回"的半轮，会让 `turn_no` 出现空洞，前端渲染和后续评价模块都要为它写特例。宁可丢掉一句失败的文本，也不要制造两种数据形状。

### D-3 会话级串行

`begin_turn` 事务内先查：

```sql
SELECT idempotency_key FROM request_log
WHERE session_id=? AND status='pending' LIMIT 1
```

查到就返回 `duplicate_in_flight`（409）。不改表结构，代价是一条 SELECT。

### D-4 提示词：结构来自模板，措辞来自设计文档 10.1

- 学生的**口癖、回避方式**放在案例的 `private_json.expression`，不同案例可以不同；
- `persona.py` 只做字段填充，**不做提示词设计**；
- 填充用 `str.replace("{{alias}}", ...)` 或 `string.Template`，**禁止 `str.format`**（案例文本里出现 `{}` 会直接抛异常）。

### D-5 `/api/metrics` 补接口

`POST /api/metrics`，body：

```json
{"session_id":"s_…","turn_no":3,"asr_ms":780,"model_ms":1180,"tts_ms":310}
```

写入 `request_log.latency_ms` 的分段字段或单独表（M5 定）。允许匿名（本地演示），不做鉴权。

### D-6 模型接入

- key 只从 `config.settings.deepseek_api_key` 读；
- 换厂商只改 `.env` 的三行（`MODEL_BASE_URL` / `MODEL_NAME` / key）；
- 任何 OpenAI 兼容服务都能接，不绑定 DeepSeek。

## 4. 三条数据流

### 4.1 对话流（M2 之后完整）

```
POST /api/chat
  → api/chat.py        校验 session 存在且 active
  → repo.begin_turn    事务：占幂等键 + 查 pending + 分配 turn_no + 写 teacher 行
  → persona.build     拼 system（唯一读私设）+ 历史裁剪
  → model.call_model  事务外调模型（不许在事务里，否则 SQLite 写锁被网络 IO 拖住）
  → guard.check       输出黑名单
  → repo.finish_turn   事务：写 student 行 + request_log 置 done + 缓存响应
  → 返回 {turn_no, reply_text, usage, latency_ms}
```

### 4.2 幂等流

```
同 key 再来
  ├─ request_log.status=done    → 直接返回 response_json（不调模型、不计费）
  ├─ request_log.status=pending → 409 duplicate_in_flight（不并发）
  ├─ request_log.status=failed  → 重置 pending，重新走一遍
  └─ request_hash 不一致        → 422 idempotency_mismatch
```

### 4.3 私有设定流

```
cases.private_json  ──► persona.py ──► system prompt ──► 模型
        │                    │
        │                    └─► 永不返回接口、永不写日志
        └─► guard.private_keywords ──► 输出后置检查（弱保险）
```

```powershell

git add -A
git commit -m "M2: 加 /api/chat"
git tag m2
git push origin main --tags              # 推到远程（异地备份）
```

**远程仓库**：`git@github.com:lovezexiaoze/tanxin.git`（私有）
- 认证方式：SSH 密钥 `C:\Users\35077\.ssh\id_ed25519_tanxin`，已加进 GitHub 账号
- 推送前必查：`git grep -n "sk-" -- .` 应为空，`.env` 必须不在跟踪列表里
- 换电脑恢复：`git clone git@github.com:lovezexiaoze/tanxin.git`，然后重建 `.env` 与 `.venv`

| 约定 | 说明 |
|---|---|
| 分支 | 只用一个 `main`；实验性改动开 `feat/xxx`，合回 main 再删 |
| 标签 | 每个里程碑一个：`m0` `m1` `m2` … 演示前打 `demo-YYYYMMDD` |

**回滚代码**：`git checkout m1 -- backend/app/`；**回滚数据**：见 5.2。


文件名 `tanxin-YYYYMMDD-HHMMSS.db`。**改 schema 之前必须先备份**（SQLite 删列改列成本高）。

## 6. 扩展点地图

后期加功能时，按这张表找落点，不要新开一层。

| 要加的功能 | 动哪里 | 不用动 |
|---|---|---|
| 新增案例（六类情境） | `db/repo.py` 的 `_seed_cases`，或写 `scripts/import_cases.py` 从 JSON 灌入 | 接口、前端 |
| 新增接口 | `api/` 加文件 → `main.py` 挂路由 | services/db |
| 换模型厂商 | 只改 `.env` | 全部代码（D6） |
| 换识别方案（云端 ASR） | `frontend/js/speech.js` 的实现层，接口形状不变 | 后端全部 |
| 加评价模块（五维复盘） | 新建 `services/judge.py` + `api/review.py`，复用 `turns` 与 RAG | 对话链路 |
| 加多用户 | `sessions` 加 `owner_id`，`deps.py` 注入当前用户，`api` 加归属校验 | 数据流 |
| 加流式输出 | `services/model.py` 加 `stream=True` 分支 + `api/chat.py` 用 SSE | 数据层 |
| 换 PostgreSQL | `db/repo.py` 换连接与少量方言（D4 已按可迁移设计） | api/services |

## 7. 开发与验证流程

每个里程碑固定四步，**做完一个再开下一个**：

1. **写代码**：只碰该里程碑允许的文件；
2. **本地验证**：`scripts\check_boundaries.py` + `pytest backend\tests -q`；
3. **接口验证**：按 CHANGELOG 里记的 curl 命令逐条打；
4. **提交**：`git commit` + `git tag`，并在 CHANGELOG 追加一段。

### 手动验收用的固定命令

```powershell
# 健康检查
curl.exe -sS http://127.0.0.1:8000/api/health

# 建会话
curl.exe -sS -X POST -H "Content-Type: application/json" --data-binary "@scripts\body-session.json" ^
  http://127.0.0.1:8000/api/sessions
```

> Windows 下 curl 传中文 body 会被命令行编码破坏，**一律用 `--data-binary "@文件"`**，文件用 UTF-8 无 BOM。

## 9. 常见改动 SOP

### 加一个接口

1. `api/xxx.py` 建 `router`，只做校验与组装；
2. 业务逻辑放 `services/`，SQL 放 `db/repo.py`；
3. `main.py` 里 `app.include_router(xxx.router)`；
4. 错误一律 `raise errors.ApiError(状态码, 错误码, 中文说明, 可重试)`；
5. 在 CHANGELOG 记一条 curl 示例。

### 改提示词

1. 改 `persona.py` 的模板文本；
2. 用 `scripts\replay.py`（M2 提供）跑一遍 `fixtures/round1.json`，看是否还像人；
3. 若改了结构（字段增减），同步改设计文档 10.x 并升版。

### 改数据库结构

1. **先备份**：`.\scripts\backup-db.ps1`；
2. 新增字段写 `migrations\000X_xxx.sql`，启动时按 `PRAGMA user_version` 顺序执行；
3. 不删列、不改列类型（SQLite 限制）；
4. 记录到 CHANGELOG。

### 换模型

只改 `.env` 三行；改完打一次 `curl /api/health`，再跑一轮对话确认语气没崩。
